# 30 — API Specification (Conventions)

## 1. Base and versioning

- Public base URL: `{APP_URL}/api/v1` (served through the Next.js BFF proxy). FastAPI listens at `{API_INTERNAL_URL}/api/v1` and is not directly exposed except via the proxy (requests without `X-Nova-Proxy-Secret` get 404).
- Version in path (`/v1`). Backward-compatible changes (new optional fields, new endpoints, new enum values documented as "clients must ignore unknown values") ship within v1. Breaking changes require `/v2` with ≥ 6 months overlap for API-key clients.
- OpenAPI 3.1 generated by FastAPI at `/api/v1/openapi.json` (available in non-production envs; in production only to admins). The committed web type file is generated from it (`make api-types`).
- Health endpoints outside version: `/healthz`, `/readyz`.

## 2. Authentication

| Method | Header/Cookie | Notes |
|---|---|---|
| Session | `Cookie: nova_session=…` | Browser; CSRF header required on unsafe methods |
| API key | `Authorization: Bearer nova_sk_…` | Scoped; no CSRF |
| Webhook | `X-Razorpay-Signature` | Only `/webhooks/razorpay` |

Details in `09_AUTHENTICATION.md`.

## 3. Authorization

- Ownership enforced in services; foreign/missing → `404 RESOURCE_NOT_FOUND`.
- Roles for `/admin/*` (`require_role`); support vs admin per endpoint in `31_API_ENDPOINTS.md`.
- API key scopes: `chat:write`, `conversations:read`, `conversations:write`, `files:read`, `files:write`, `memories:read`, `usage:read`. Missing scope → `403 INSUFFICIENT_SCOPE`.

## 4. Requests

- `Content-Type: application/json; charset=utf-8` for bodies (except multipart voice upload).
- JSON field names `snake_case`.
- Max JSON body 1 MB (proxy and FastAPI middleware); `413 PAYLOAD_TOO_LARGE`.
- Unknown fields rejected (`model_config = ConfigDict(extra="forbid")`) → `422 VALIDATION_ERROR`.
- Strings trimmed where documented; empty strings rejected where a value is required.
- Timestamps ISO-8601 UTC with `Z`. IDs are UUID strings.
- Headers:
  - `X-Request-ID` (optional client-provided, ≤ 64 chars `[A-Za-z0-9-_]`; otherwise generated) — echoed in responses.
  - `Idempotency-Key` (UUID) — supported on message-creating endpoints, `POST /files`, `POST /billing/subscriptions`, `POST /api-keys`, `POST /users/me/exports`. Stored 24 h in Redis `nova:{env}:idem:{principal}:{route}:{key}` → cached response for non-message endpoints (same status + body); message endpoints use DB idempotency (`13_STREAMING.md` §9). Same key + different body hash → `409 IDEMPOTENCY_KEY_REUSED`.

## 5. Responses

Success envelope:

```json
{ "data": { ... } }                          // single resource
{ "data": [ ... ], "page": { "next_cursor": "…"|null, "has_more": true } }   // lists
{ "data": ..., "meta": { ... } }             // optional extra metadata
```

- `201 Created` for creations (with `Location` header for addressable resources), `202 Accepted` for queued work, `204 No Content` for deletions/logout with no body.
- Nullable fields are always present (explicit `null`), never omitted.
- Enum fields are lowercase snake_case strings.
- Money: integer minor units (`amount_paise`) + `currency`.

## 6. Pagination

Cursor-based (keyset) everywhere:
- Query: `limit` (default 30, max 100; messages default 50), `cursor` (opaque base64url JSON, signed with HMAC to prevent tampering: `payload.sig`), direction implied by endpoint.
- Response `page.next_cursor` null when no more.
- Invalid/tampered cursor → `400 INVALID_CURSOR`.
- Offset pagination only in admin tables where total counts are needed (`page`, `page_size` ≤ 100, response `meta.total`), with total computed by `count(*)` capped at 10,000 (`meta.total_capped: true`).

## 7. Filtering and sorting

- Filters are explicit query parameters documented per endpoint (e.g., `archived=true`, `status=ready`, `kind=document`, `q=`). No generic filter language.
- Sorting: `sort` parameter with allow-listed values per endpoint, `-` prefix for descending (e.g., `sort=-created_at`); default documented per endpoint. Unknown sort → `422 VALIDATION_ERROR`.
- Date ranges: `from`, `to` (ISO dates, inclusive-exclusive).

## 8. Errors

Envelope (`32_ERROR_HANDLING.md`):

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Human readable, safe.", "details": [ { "field": "title", "issue": "too_long" } ], "request_id": "…", "retryable": false } }
```

Rate limit / quota errors include `Retry-After` header and `RateLimit-*` headers (`34_RATE_LIMITING.md`).

## 9. Streaming

SSE per `13_STREAMING.md`. Pre-stream errors are JSON. `Accept` negotiation for message endpoints.

## 10. Caching headers

- Authenticated JSON responses: `Cache-Control: no-store`.
- Public endpoints (`GET /billing/plans`): `Cache-Control: public, max-age=300`.
- `ETag` not used in v1.

## 11. CORS

Not needed for browsers (same origin via proxy). FastAPI CORS middleware is **disabled**; the proxy rejects cross-origin preflights for unsafe methods (no `Access-Control-Allow-*` headers are emitted). API-key clients are server-side and unaffected.

## 12. Router conventions (FastAPI)

```python
router = APIRouter(prefix="/conversations", tags=["conversations"])

@router.patch("/{conversation_id}", response_model=Envelope[ConversationOut],
              dependencies=[Depends(require_csrf), Depends(rate_limit("conversations_write"))])
async def update_conversation(
    conversation_id: UUID,
    body: ConversationUpdateIn,
    principal: Principal = Depends(require_scopes("conversations:write")),
    service: ConversationService = Depends(get_conversation_service),
) -> Envelope[ConversationOut]:
    conv = await service.update(principal, conversation_id, body)
    return Envelope(data=ConversationOut.from_domain(conv))
```

- Every endpoint declares `response_model` and `responses={...}` for documented errors (OpenAPI accuracy).
- `operation_id` = `<tag>_<action>` (e.g., `conversations_update`) — used for generated client names.
